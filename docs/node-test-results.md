# Node.js test-suite results

Results of running Node.js v24.21.0's own tests from `test/parallel` against `--node-compat`, with `tests/node-harness/run-node-tests.mjs`. `tests/node-harness/tests.txt` selects every test except those of Node's build tooling, V8's heap and trace tooling, the inspector and QUIC. A test passes if it exits with status 0. Tests that need runtime flags the runtime rejects, child processes, workers, `cluster` or the inspector are skipped without running, and tests that call `common.skip()` count as skipped.

## Known blockers

| Blocker | Failing | Skipped | What it is |
| --- | ---: | ---: | --- |
| The HTTP client | 53 | 0 | Tests run with `--node-http-listen`, so their servers accept connections, and most remaining HTTP failures are on the client side. The client is built on reqwest, which adds `accept: */*`, lowercases header names, normalizes paths, strips hop-by-hop headers and reports the standard reason phrase. 1xx responses, `Agent` socket pools and `req.socket` are not exposed. |
| Child processes, workers, cluster and the inspector | 0 | 382 | WASI has no processes or threads, so these tests are skipped without running. |
| Unsupported runtime flags | 0 | 125 | Tests that need a runtime flag the runtime rejects, such as `--allow-natives-syntax` or the permission model's flags, are skipped without running. The runtime gets the other flags with `--allow-node-runtime-flags`. |
| Unimplemented APIs | 241 | 0 | Stubs that throw `ERR_METHOD_NOT_IMPLEMENTED`, such as brotli and zstd compression, crypto keys and ciphers (there is no OpenSSL), `net` IPC paths and `dgram`. The blockers list below names each API. |
| Engine differences | 23 | 0 | SpiderMonkey has no `SharedArrayBuffer` global here, `vm` and `v8` are stubs, and stack traces have SpiderMonkey's frames. |
| Timing and resource exhaustion | 24 | 0 | Tests that time out waiting for events that never come, and crashes. Each needs a look of its own. |
